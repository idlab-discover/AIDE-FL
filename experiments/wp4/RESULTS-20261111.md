# WP4 smoke-sensor participant-count comparison

These experiments ran on 11 November 2026 using Flower 1.43.0 and the real Smoke Detection Dataset. They trained and validated 60 models, reloaded every saved model and checked its predictions. Participants ran in one Python process. This is model-quality evidence under simulated ownership, not a distributed deployment or system-scaling result. The date is after the project's stated eligible period.

## Configuration and retained evidence

The comparison holds the total dataset, chronological split and training budget fixed while dividing training rows among two, four or eight simulated participants. Each participant count uses seeds 17, 42 and 73, twenty rounds and five local SAGA iterations per round. Each seed trains all participant-local baselines, a pooled centralised baseline and Flower FedAvg. There are 12, 18 and 30 completed models respectively. Centralised baselines repeat the same three seeds at each participant count; these repetitions are not independent experiments.

The retained source archive has SHA-256 `9c1fb61d38f5efa0293c3f2c36f7c4af2556ee0a177653adaaaeb1ea78aceff8`. Training uses 31,254 rows, validation 12,465 and testing 18,789. The chronological boundaries have 60-second gaps. Twelve sensor inputs exclude timestamps, counters and exported row indexes. The common scaler fits training rows only. Participants receive disjoint stratified training partitions from one source dataset, not data from independent organisations. The final fixed round is tested without selecting a checkpoint from test results.

Completed experiment directories under `final-report/working/wp4-validation/` are:

- `sensor-iid-c2-20261111-v143`
- `sensor-iid-c4-20261111-v143`
- `sensor-iid-c8-20261111-v143`

Each directory retains an experiment manifest, source snapshots and hashes, package versions, exact row assignments, per-round metrics, final predictions and reloadable model bundles. The source snapshots include the adapter and local Flower identity helper. W&B publication uses the [aide-wp4-smoke project](https://forge.coreweave.com/wandb/strgen/aide-wp4-smoke); all 71 fresh model runs finished remotely, and every retained history measurement, summary value and committed artifact was verified. Each directory's `wandb-receipts.json` records the verified remote run links. Earlier directories without the `v143` suffix contain preliminary or failed diagnostics and are excluded from this comparison.

Increasing participant count does not improve the ranking or balanced accuracy of this fixed-budget model. The two-client result is stronger than the four- and eight-client results on those measures. Log loss decreases while AUC worsens, so a single metric would give an incomplete account. Federation does not outperform pooled central training on F1, balanced accuracy or AUC here.

## Validation and limitations

The separate earlier validation period is substantially harder for this model. Mean final validation balanced accuracy is 0.5332, 0.5484 and 0.5710 for two, four and eight clients, respectively. Mean validation log loss is 2.3155, 1.9503 and 1.6800. All exceed the untrained 0.5-probability baseline's log loss of 0.6931. These runs demonstrate executed training and validation, but do not establish a model ready for deployment. The contrast between validation and test periods should accompany report figures rather than be hidden by the higher test F1.

The runner now distinguishes sample-weighted client metrics before aggregation, named `train_*`, from the resulting model's pooled training metrics, named `global_train_*`. Summaries retain initial and final validation scores and coefficient norms. For a local-only model, pooled training metrics also evaluate other clients' rows after training; those rows do not update its coefficients. Shared preprocessing still pools training moments and is not private. The temporal split was selected previously after inspecting class coverage, so the study remains exploratory.

Four- and eight-client runs exposed a correctness bug: averaging class-label metadata with floating participant weights could turn label 1 into a nearby non-integer. The adapter now keeps class labels in validated scenario configuration and aggregates only coefficients and intercepts. Concurrent experiments also exposed a cache race caused by rewriting one extracted CSV. The runner now reads CSV bytes from the cached archive and publishes downloaded archives atomically.

The WP4 tests pass on Flower 1.43. They cover temporal separation, participant ownership, the shared-cache regression, actual local/central/federated training with unequal participant sizes, training-only scaler fitting and saved-model probability agreement. The synthetic fixture used by the regression test is separate from the real dataset used for every reported experiment. InfluxDB is unnecessary for this fixed timestamped-data comparison.

## Fresh privacy diagnostics

The directory `sensor-secagg-fhe-20261111-v143` retains seven additional three-client models using seed 17, five rounds and five local iterations. Plaintext FedAvg, native SecAgg+ and experimental CKKS aggregation finish with identical test classification labels, balanced accuracy 0.6946 and F1 0.8551. CKKS's maximum per-round discrepancy from the plaintext aggregate is `2.02e-13`; encrypted uploads total 10,028,812 bytes. This measures ciphertext payload, not network throughput or end-to-end performance. SecAgg+'s maximum discrepancy is `2.22e-6`, across twenty protocol stages and sixty replies. Those replies contain no plaintext model arrays. These are single-seed correctness diagnostics. The process holds plaintext reference updates and the CKKS secret key; the runs do not establish process isolation or a deployment privacy guarantee. CKKS supplies approximate homomorphic addition for FedAvg, without threshold decryption or bootstrapping.

The separate TensorFlow experiment in `sensor-dp-20261111-v143` contains four models trained with three clients, ten rounds, one local epoch and seed 17. A clipping-only control distinguishes clipping's effect from added DP noise. All use uniform client weights and the same fixed feature scaling and model configuration.

| Method | Test balanced accuracy | Test F1 | Test ROC AUC | Epsilon at delta 1e-5 |
| --- | ---: | ---: | ---: | ---: |
| Ordinary FedAvg | 0.5410 | 0.8227 | 0.2545 | No DP guarantee |
| Clipping only, norm 0.2 | 0.5403 | 0.8226 | 0.2599 | No DP guarantee |
| Central DP, noise multiplier 0.5 | 0.5391 | 0.8222 | 0.2678 | 48.8017 |
| Central DP, noise multiplier 1.0 | 0.5364 | 0.8061 | 0.2432 | 19.0536 |

Accounting covers ten model releases in each individual run without sampling amplification. The large epsilon values and poor discrimination make these diagnostic results, not evidence of a strong privacy–utility outcome. Central DP trusts the aggregation server; separate runs require composition. Public benchmark evaluation is explicitly enabled in this experiment. Private runtime modes suppress private training metrics, but that does not make the benchmark's exported evaluation metrics private. See [the privacy configuration and trust boundaries](../../flower/PRIVACY.md).

The 60 participant-count models, seven encryption-comparison models and four DP models total 71 fresh model runs. The saved checksums of all 67 scikit-learn run directories were verified after training. This total includes repeated baselines and does not count independent datasets or independent sites.
